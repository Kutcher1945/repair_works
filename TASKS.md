# Задачи проекта «Ремонтные работы»

Система учёта и мониторинга дорожных ремонтных работ города Алматы.  
Стек: **Next.js 16 (App Router, Turbopack)** + **Django 4.2 / DRF** + **JWT-авторизация**.

---

## 1. Аутентификация и авторизация

**Файлы:** `app/lib/auth.ts`, `app/context/auth-context.tsx`, `app/page.tsx`

- Реализована страница входа (`/`) с полями Email и Пароль.
- Интеграция с эндпоинтом `POST /api/v1/common/auth/login/` — получение JWT-токенов (`access` + `refresh`).
- Токены сохраняются в `localStorage` (`rw_access`, `rw_refresh`).
- Автоматическое обновление `access`-токена через `refresh` при получении `401`.
- Функция `apiFetch` — обёртка над `fetch` с автоматической подстановкой Bearer-заголовка и перехватом истёкших сессий.
- `AuthProvider` + `useAuth()` — глобальный контекст пользователя: хранит `User`, `isLoading`, методы `login`, `logout`, `setUser`.
- Защита маршрутов: если токена нет — редирект на `/`.
- Тип `User` расширен всеми полями API: `id`, `email`, `first_name`, `last_name`, `phone`, `role`, `organization_name`, `date_joined`, `is_active`.

## 2. Основной layout дашборда

**Файл:** `app/dashboard/layout.tsx`

- Боковое меню (sidebar) с двумя состояниями: развёрнутое (240 px) и свёрнутое (72 px).
- Состояние сайдбара сохраняется в `localStorage`.
- Анимированная кнопка сворачивания с иконкой-стрелкой.
- Логотип SVG в шапке сайдбара (полный при развёрнутом, только иконка при свёрнутом).
- Навигация с 7 пунктами (нумерованными), с подсветкой активного маршрута, левым акцент-баром и анимированной точкой.
- Пункт «Пользователи» скрыт для роли `employee` — виден только `admin`.
- Нижняя секция сайдбара с аватаром (инициалы), именем, названием организации, email — кликабельна, ведёт на `/dashboard/profile`.
- Шапка (header): название текущего раздела слева, колокол уведомлений + имя пользователя справа. Кнопка с именем ведёт на личный кабинет.
- Колокол уведомлений: загружает уведомления с `GET /api/v1/common/notifications/`, поллинг каждые 30 секунд, бейдж с количеством непрочитанных, кнопка «Прочитать все».
- Тёмно-синий градиент сайдбара с сеточной текстурой и радиальным свечением внизу.

**Порядок навигации:**
1. Главная
2. Заявки
3. Карта
4. Отчёты
5. Пользователи *(admin only)*
6. Личный кабинет
7. Настройки

## 3. Главная страница дашборда

**Файл:** `app/dashboard/page.tsx`

- Приветственный баннер в стиле бренда: тёмно-синий градиент, сеточная текстура, радиальное свечение.
  - Показывает название организации (если есть), приветствие по времени суток («Доброе утро / Добрый день / Добрый вечер / Доброй ночи»), имя пользователя и текущую дату.
  - Кнопка «Новая заявка».
- 4 карточки с показателями: всего заявок, активных, на проверке, завершено.
- Таблица «Последние заявки» — 5 самых свежих записей с колонками: №, Название, Адрес, Статус, Период.
- Статусы окрашены цветными бейджами (`draft`, `pending_review`, `needs_revision`, `active`, `completed`, `cancelled`).

- Индикаторы просрочки: показывает сколько дней осталось или просрочено.

## 5. Создание новой заявки

**Файл:** `app/dashboard/repairs/new/page.tsx`

Форма разбита на 6 секций:

**Секция 1 — Общая информация:**
- Наименование проекта (обязательное).
- Описание работ.
- Заказчик и Телефон заказчика — read-only поля, заполняются автоматически из профиля пользователя.
- Подрядчик: наименование, телефон, описание работ подрядчика.

**Секция 2 — Место проведения работ:**
- Выбор района из справочника (`/api/v1/repair-works/ref_district/`).
- Адрес (текстовое поле).
- Участок дороги (от/до).
- Интерактивная карта (`DrawMap`) — нанесение линии/полигона/точки на Leaflet-карту; геометрия сохраняется как GeoJSON.

**Секция 3 — Сроки:**
- Плановая дата начала и окончания (обязательные), с валидацией что конец не раньше начала.

**Секция 4 — Перекрытие дороги:**
- Чекбокс «работы предполагают перекрытие», при включении открывается поле описания.

**Секция 5 — Документы** (4 отдельные зоны загрузки с разными `doc_type`):
- Проектная документация (`project_docs`)
- Временная схема ОДД (`traffic_scheme`)
- Договор (`contract`)
- Дополнительные документы (`additional`)

**Секция 6 — Фотофиксация:**
- Загрузка фото «до начала работ», превью сеткой 4 колонки.

Дополнительно:
- Защита от случайного ухода со страницы (`UnsavedChangesGuard`) — модальное окно подтверждения.
- Последовательная загрузка файлов с отображением прогресса в кнопке («Загрузка документа 2/3…»).

## 8. Аналитика и отчёты

**Файл:** `app/dashboard/reports/page.tsx`

- Приветственный баннер (тёмно-синий, показывает «Сводная аналитика» для admin или название организации для employee).
- **6 KPI-карточек:** всего заявок, активных, завершено, просрочено, средний срок выполнения, процент выполнения в срок.
- **SVG-график по месяцам** (`MonthlyChart`) — столбчатая диаграмма за 7 месяцев с тремя слоями: создано / завершено / активно. Реализовано без внешних библиотек на чистом SVG.
- **Кольцевая диаграмма** (`DonutChart`) — распределение по статусам. SVG `stroke-dasharray` без библиотек.
- **Кольца прогресса** (`ProgressRing`) — процент завершения, выполнено в срок, просрочено.
- **Разбивка по районам** (`DistrictTable`) — таблица с мини-прогресс-барами.
- **Заявки с истекающим сроком** (`ExpiringSoon`) — заявки с дедлайном в ближайшие 14 дней, цветовая индикация срочности.
- **Таблица просроченных** (`OverdueTable`).
- **Разбивка по организациям** (`OrgTable`) — только для admin, с полосами процента завершения.

## 10. Личный кабинет

**Файл:** `app/dashboard/profile/page.tsx`

- **Баннер** на всю ширину: аватар с инициалами, полное имя, организация, роль-бейдж, email, дата регистрации, статус «Активен».
- **Двухколоночный layout** для заполнения пространства:
  - *Левая колонка:* форма редактирования личных данных (имя, фамилия, телефон; email read-only) + блок с советами по безопасности.
  - *Правая колонка:* карточка аккаунта (read-only: email, роль, организация, дата регистрации) + форма смены пароля.
- **Смена пароля:** текущий пароль, новый пароль, повторите — с кнопкой показать/скрыть, валидацией совпадения и индикатором надёжности (4 уровня: слишком короткий / приемлемый / хороший / надёжный).
- После сохранения имя/организация обновляются в хедере и сайдбаре мгновенно (через `setUser` в `AuthContext`).
- Доступен по клику на имя пользователя в хедере или сайдбаре, а также через пункт «6 — Личный кабинет» в навигации.

## 12. UI/UX доработки

### Отображение организации
- Название организации пользователя отображается в сайдбаре (под именем, голубым цветом), в хедере (серый подзаголовок под именем), в баннере главной и страницы отчётов.
- В таблице заявок колонка «Заказчик» показывает `organization_name` из самой заявки.

### Брендинг и визуальный стиль
- Единый дизайн-язык: тёмно-синий градиент `#06152A → #0D2344 → #12345B` для баннеров и сайдбара.
- Сеточная текстура и радиальные свечения как декоративные элементы.
- Цветовая система статусов: черновик (серый), на проверке (оранжевый), на доработке (красный), активный (зелёный), завершён (синий), аннулирован (серый).
- Все иконки — кастомные SVG, без внешних библиотек иконок.

### Защита несохранённых изменений
- Компонент `UnsavedChangesGuard` отслеживает изменения в формах и показывает модальное окно при попытке покинуть страницу.

### Исправление TypeScript / сборки
- Тип `User` дополнен полями `date_joined`, `username`, `phone`, `is_active` — устранена ошибка сборки на Vercel.
- Убран небезопасный каст `(user as { organization_name?: string })` в settings — поле добавлено в тип.
